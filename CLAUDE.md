# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-page static portfolio piece ("PLINTH / 001") presenting a 3D-modeling case study for a lounge chair — reference plates, material/mood variants, and a live 3D viewer. There is no build system, package manager, framework, or test suite: it's plain HTML/CSS/vanilla JS served as static files, with three.js loaded from a CDN via an import map.

## Running / previewing

There's no dev server or build step. Open [index.html](index.html) directly in a browser, or serve the folder over HTTP so ES module imports and `fetch` (used by the viewer's fallback probe) work correctly, e.g.:

```
npx serve .
# or
python -m http.server
```

Opening via `file://` will break the module viewer (`assets/js/viewer.js`) in most browsers due to CORS restrictions on ES modules — use a local server when testing the 3D viewer.

There is no lint/test/build command to run after changes; verify visually in the browser.

## Cache-busting convention

`index.html` references `assets/css/style.css` and the two JS files with `?v=N` query strings (e.g. `style.css?v=60`, `main.js?v=24`, `viewer.js?v=5`). **Bump the relevant `?v=` number whenever you edit that file** — this is the only cache invalidation mechanism in use, there's no build hash.

## Architecture

Everything hangs off one file, [index.html](index.html), organized as a sequence of `<section class="sheet">` blocks representing "contact sheet" plates (index grid, clay-material views, renders, mood variants, postpro views, interior, 3D viewer). Two independent, dependency-free JS files run against this markup:

- **[assets/js/main.js](assets/js/main.js)** — all page chrome and interaction that doesn't need 3D: scroll progress bar, nav solid/scroll-spy state, `IntersectionObserver`-based reveal-on-scroll, mobile menu, the film modal, the image lightbox, and the `#interior` two-frame plate sliders (`.ishot`, see the Interior note below). The lightbox groups images by the closest ancestor's `data-gallery` attribute and reads `data-full`/`data-caption` off each `.tile`/`.bleed` button — new galleries just need those data attributes, no JS changes. Also includes a drag-to-scrub turntable fallback (`#viewerFallback`, 36 numbered frames under `assets/img/turntable/`) and a 7s watchdog that swaps to it if no `<canvas>` appears in `#viewerCanvas` (i.e. three.js/CDN failed).
- **[assets/js/viewer.js](assets/js/viewer.js)** — the three.js viewer, loaded as an ES module (see the `importmap` in `index.html` pinning `three@0.169.0` from jsdelivr; bump both the importmap and the DRACOLoader decoder path together if upgrading). Renders **two panes side by side, one per LOD** (`chair_low.glb` and `chair_high.glb`), each loaded via `GLTFLoader` + `DRACOLoader`. `createPane()` is a factory — renderer, scene, camera, controls and clay material are all per-instance, because a PMREM environment texture is bound to the WebGL context that generated it and can't be shared across two renderers.
  - **The cameras are mirrored on purpose**: whichever pane you drag leads, the other copies its position/target. Comparing two LODs only means something at an identical angle; unsynced, it's just two chairs in different poses. The `syncing` flag guards against the feedback loop (`controls.update()` re-fires `change`). `autoRotate` lives on **one** pane only (`panes[0]`) — enabled on both, each would write its own camera every frame and fight the mirror. Two separate flags drive it: `spinWanted` (the button, an explicit preference) and `dragging` (momentary, between OrbitControls' `start` and `end`), so a drag only **pauses** the spin and it resumes on release — only the button turns it off for good. `mirror()` also has to blank `autoRotate` around its `controls.update()`: with it on, that call advances the rotation a second time and the pane spins faster than `autoRotateSpeed`.
  - There is no view-preset or LOD-switch UI any more (the `front/three/side/top` chips and `[data-lod]` buttons are gone): with both models on screen there is nothing to switch between. Only Wireframe / Rotazione auto / Schermo intero remain, and each applies to both panes.
  - **Contact AO** comes from a `GTAOPass` in an `EffectComposer` per pane (`RenderPass → GTAO → OutputPass`). The `OutputPass` is not optional: rendering through a composer means *it*, not the renderer, applies tone mapping and the sRGB conversion — drop it and the image comes out raw and washed out. AO is always on — there is no toggle; composer construction is wrapped in `try` and falls back to a direct `renderer.render` on hardware that can't build it. `CONFIG.ao.radius` is in **world units**, so it tracks model scale (the chair is ~1 unit tall); `setSceneClipBox()` bounds the AO to the model's bounding box after framing. The clay colour was darkened to `0x757169` when AO went in — on the original near-white it barely registered. There's a floor to that, though: the page is near-black (`--bg #0b0b0c`), so going much darker starts losing the silhouette against the background.
  - GLBs are expected to ship *without* materials — a clay `MeshStandardMaterial` is applied when the glTF has no materials, so the shape reads on its own. Each pane fails independently: a GLB that won't load drops **that** pane to the procedural box proxy (`buildProxy()`) while its neighbour stays up. GLTF load and scene assembly are deliberately separated (see the comment above `load`) so an assembly bug isn't miscategorized as a network failure.
  - The ids `viewerStage` and `viewerCanvas` are load-bearing for **main.js**, not for viewer.js: fullscreen targets the first, and the 7s turntable watchdog polls the second for a `<canvas>`. Renaming them silently breaks both. The turntable fallback covers the whole pair (`position:absolute; inset:0` plus its own background), so showing it is enough — no need to hide each pane.

Styling ([assets/css/style.css](assets/css/style.css)) is one file built around a strict 12-column "sheet" grid with 1px hairline gutters standing in for all borders (`--line` background showing through `gap`, not actual `border` rules) — see the "The sheet" and "Plates" sections. Key conventions to preserve when adding markup:
- Grid spans use utility classes `.w2/.w3/.w6/.w9/.w12` scoped as `.sheet > .wN`.
- Repeating image groups use `.strip` (5 or 6 col sub-grid) + `.tile` buttons. Plates used to be auto-numbered via CSS `counter(plate)` on `.tile::before`, with a `.tile--bare` modifier to opt one out without breaking the sequence; **all of that is gone** — the counter, its `counter-reset:plate` on `body`, and the class. What labels an image now is text: `.plate-pill` (top-right of a plate) and `.fact-plate__tag` (bottom-left, in the index cards). Don't reintroduce a numeric overlay alongside them.
- Key/value blocks (pipeline steps) reuse `.data.data--1` rather than one-off styles.
- All CSS custom properties (colors, spacing, easing) are defined once on `:root`; there's no dark/light theme toggle (site is dark-only, `color-scheme:dark`).
- Responsive behavior remaps grid spans at `1000px`/`640px` breakpoints rather than changing structure.

## Content notes

- `index.html` currently has `<meta name="robots" content="noindex, nofollow">` with a comment explaining it's intentional while renders are placeholders — remove only when told the page is ready to publish.
- Some external links (Portfolio, ArtStation, LinkedIn in the footer) are still placeholders (`href="#"`) — don't treat their absence as a bug unless asked to wire them up.
- Comments in the JS/CSS are a mix of English and Portuguese; match whichever language a given comment block already uses when editing nearby.
- There is no Specs/delivery section (removed by request) — the `.spec` table CSS and the `downloads/` PDF/MP4 links that lived only in that section were removed along with it. Nav no longer has a `#specs` entry; the `01 3D` link now carries the `nav__link--cta` styling that `Specs` used to have.
- The `#interior` section opens with a **three-plate concept row** (`.strip.strip--concept`, its own `data-gallery="interior-concept"`): reference → process → final (`interior-concept`, `interior-concept2`, `interior-final`). The first two are 33/14 and the last is 16/9, and the row's columns are `297fr 297fr 224fr` — which is exactly `33/14 : 33/14 : 16/9` ×126. That's what makes all three come out the **same height with nothing cropped**; with `1fr` each, the 16/9 plate would render taller than its neighbours and the row would lose its baseline. Don't change one of those three numbers without recomputing the others from the real file ratios.
- Below it, the same section carries a **time-of-day study**: a `.strip.strip--2` (2×2) of four `.tile.ar-cine` plates — `interior-morning`, `interior-afternoon`, `interior-sunset`, `interior-night`, in that chronological order. All four are the **same camera** on the same scene with only the lighting changed, so the framing must stay identical between them: they use `.ar-cine` (`33/14`, the exact ratio of the source files) precisely so `object-fit:cover` never crops, since any crop would misalign one plate against the others and break the comparison. Don't reorder them and don't switch them to a cropping ratio. `.strip--2` holds 2 columns down to 1000px and stacks to 1 at 640px (a 2.36:1 image at half a phone screen is an unreadable sliver).
  - The **"Render grezzo" plate in the concept row is a six-frame `.ishot`** — the same camera in six render passes (beauty → AO → clay → shaded viewport → material ID → clay viewport). It differs from the time-of-day sliders in one way: each `<img>` carries a **`data-pill`**, and the slider rewrites the `.plate-pill` text as that frame comes up, because here what changes between frames *is* the pass. Frames without `data-pill` leave the label alone — that's the time-of-day case, where both frames are the same hour and only the people change. All six share the exact source ratio, so nothing shifts on the flip.
  - **Each of the four time-of-day plates is a two-frame mini-slider** (`.ishot`): the empty render and the same render with people (`interior-<time>.webp` / `interior-<time>-people.webp`). It cross-fades on opacity, never translates — the camera is identical between the two frames, so sliding would imply they're different places. Auto-advances every 10s (`SHOT_MS` in main.js) with a **random 2–10s first delay per plate**, deliberately: in phase, all four would flip at the same instant and the row would strobe. Only the start is random; frame order stays a strict alternation so the arrows and the timer never disagree about what's next. It pauses on hover/focus (WCAG 2.2.2), off-screen, and with the tab backgrounded, and doesn't auto-advance at all under `prefers-reduced-motion`.
  - Structural constraint worth knowing before you touch this markup: the lightbox is a **delegated** handler matching `closest('.tile[data-full]')`, so `data-full`/`data-caption` must stay on the outer `.tile` div — the slider keeps them in sync with the visible frame on every change. The arrows are **siblings** of `.ishot__open`, not children: a `<button>` inside a `<button>` is invalid HTML. They also `stopPropagation()`, otherwise changing frames would bubble up and open the lightbox.
  - This section previously held one `interior.webp` plate plus five `.tile--pending` placeholders; both are gone. `.tile--pending` (diagonal hatch, "Pending" label from CSS `::after`, no `data-full` so the lightbox skips it) is still defined in the stylesheet and is still the right pattern if a future row needs to hold empty slots — it's just unused right now.
  - `images/chair/interior.webp` is still in use: it's the image for the INDEX card 06 and the source for the OG share crop. Don't delete it just because this section no longer points at it.
- Nav labels are deliberately short (`Modeling`, `Postproduction`, `Interior` — not "Chaise ___"); keep that pattern for any new section link.
- The hero and the film modal play **two different files**, both H.264 with no audio track (neither source has one). Two masters live in `assets/video/` and are **not** referenced by the page — they are the encode sources:
  - `hero_new.webm` (VP9, 2208×936, 14.9MB) → source for the hero loop
  - `hero4.mp4` (H.264, 2208×936, 10 Mbps, 39.8MB) → source for the film
  
  What the page actually loads:
  - `assets/video/hero.mp4` — the background loop. 1472×624, ~910 kbps, 3.6MB.
  - `assets/video/film.mp4` — the modal. **2208×936 native** (no downscale), ~3.2 Mbps, 12.6MB, SSIM 0.98 against the master. `preload="none"`, so nothing is fetched until someone clicks *Guarda il film*.
  
  The two masters are the same footage at different quality (SSIM 0.955 between them). They used to be one VP9 webm serving both hero and film, on the reasoning that one download covers both. That was reverted because it **stuttered on Vercel**: streaming ~4 Mbps sustained, plus VP9 at that resolution falling back to *software* decode on a lot of machines, while the page also runs the viewer's two WebGL contexts. H.264 is hardware-decoded essentially everywhere. Keep the loop cheap and the film good — don't re-merge them, and don't point a `<source>` at a raw master or reintroduce a VP9/webm ahead of the mp4.
  
  `main.js` also **pauses the hero video when it scrolls out of view** (it was decoding for the whole page, competing with the 3D viewer). `.hero` sizes itself with `aspect-ratio:1472/624` — every file here is 92:39, so the ratio has never changed rather than `100svh`: at the video's own ratio `object-fit:cover` crops nothing (same reasoning as `.ar-cine`). `min-height`/`max-height` are the two escapes — a floor so the title, lede and button still fit where the ratio would give a ~165px band on a phone, and a ceiling so the hero doesn't outgrow a tall monitor. Inside those two clamps the box stops being 2.36:1 and cropping returns, which is unavoidable. If the video is ever replaced, **update `--hero-ar` to match it**, or the crop comes back. Re-encode recipe (ffmpeg, from the master):
  ```
  # loop do hero — do webm
  ffmpeg -i hero_new.webm -an -vf "scale=1472:624:flags=lanczos,hqdn3d=2:2:6:6" \n    -c:v libx264 -profile:v high -preset veryslow -crf 29 -maxrate 1800k -bufsize 3600k \n    -g 48 -keyint_min 48 -sc_threshold 0 -pix_fmt yuv420p -movflags +faststart hero.mp4
  # filme — resolucao NATIVA, do master mp4
  ffmpeg -i hero4.mp4 -an -vf "hqdn3d=1.5:1.5:5:5" \n    -c:v libx264 -profile:v high -level:v 5.0 -preset slow -crf 24 -maxrate 5000k -bufsize 10000k \n    -g 48 -keyint_min 48 -pix_fmt yuv420p -movflags +faststart film.mp4
  ```
  The `hqdn3d` denoise is deliberate: the source is a render with heavy grain, which is very expensive to compress, and the page lays its own grain over everything anyway (`body::after`). `+faststart` is not optional — without it the moov atom lands at the end of the file and the browser must download the whole thing before the first frame.
- There is no `.hero__facts` anymore. The 6 "Role / Software / Implementation / Sculpting / Studio Render / Interior Render" fact blocks used to float over the hero video as their own row, separate from the INDEX image strip below it. They're now merged: the first `.sheet` section after `.hero` holds a `.strip.strip--6` of 6 `.fact-plate` columns, each one **card** = its `.fact--dl` (icon/download + label) on top, directly followed by the matching `.tile` image, no gap between them. The pairing order is fixed and must stay 1:1: Role↔`index-1.webp`, Software↔`index-2.webp`, Implementation↔`index-3.webp`, Sculpting↔`index-4.webp`, Studio Render↔`render_perspective2.webp`, Interior Render↔`interior.webp`. If you add a 7th fact or reorder them, keep each `.fact--dl` and its `.tile` inside the same `.fact-plate` div — don't split them back into two rows.

## Sharing / SEO meta

`index.html`'s `<head>` carries a full Open Graph + Twitter Card set (title, description, `og:site_name`, `og:locale`, canonical link) plus a dedicated share image: **`assets/img/og-interior.jpg`** (1200×630, cropped from `images/chair/interior.webp`, regenerated via Pillow — center-crop to a 1.91:1 ratio then resize, not a straight resize, so nothing gets squashed). If the interior render changes, regenerate that crop rather than hand-editing it, and keep `og:image`/`twitter:image` pointed at the same file. `<meta name="robots" content="noindex, nofollow">` only affects search engines — it does **not** block social/chat link-preview scrapers (Slack, WhatsApp, iMessage, LinkedIn, etc.), so share previews work correctly even while the page stays out of Google.

## Deploy (Vercel)

`vercel.json` exists only to set `Cache-Control`. **Do not add `"//"` comment keys to it** — Vercel validates against a strict schema and rejects any additional property inside a `headers[]` entry (only `source`, `headers`, `has`, `missing` are allowed), which fails the deploy outright. Explain the rules here instead. Without it Vercel serves non-hashed static files with `must-revalidate`, so every load pays a round trip just to hear 304 — on the hero video that delays the first frame. Videos, images and `assets/css|js` are `immutable` (CSS/JS are safe because `index.html` busts them with `?v=N`); HTML has no rule at all, on purpose: Vercel already serves it with `must-revalidate`, and it must **never** be immutable since it's the file that carries the new `?v=N`.

## Asset hygiene

- Only files actually referenced by `index.html`/`main.js`/`viewer.js` should live under `images/` and `assets/img/` — this repo previously accumulated ~148MB of orphaned raw PNG exports and unused WIP folders (`assets/img/{interior,lowpoly,moods,research,sculpt,studio}`) that were never linked from the page; these were removed. Before adding new renders, wire them into a `<section class="sheet">`/`data-gallery` rather than dropping them in `images/chair/` unreferenced.
- In-use `images/chair/*.webp` are capped at 1400px on the long edge and re-encoded at quality 82 — that's plenty for the grid tile sizes they render at (see `.tile`/`.ar-*` in the CSS). Don't re-introduce full-resolution (2000px+) exports directly into this folder; keep a separate archive outside the repo for print/high-res masters.
